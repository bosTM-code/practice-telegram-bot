# Telegram-бот для автоматизації роботи з практикантами

## Опис проєкту

Цей проєкт реалізує Telegram-бота для автоматизації взаємодії між керівником практики та практикантами. Бот дає змогу централізувати типові дії в одному інтерфейсі Telegram: реєстрацію користувачів, перегляд актуальних задач, подання щоденних звітів, зміну статусу задач, адміністративний перегляд звітів і експорт даних у CSV. Такий підхід відповідає постановці завдання, де основною метою є спрощення комунікації та контроль виконання практичних завдань.

## Основні можливості

- реєстрація практиканта в системі;
- перегляд актуальних задач і дедлайнів;
- подання щоденного звіту;
- зміна статусу задачі на `in_progress` або `done`;
- перегляд звітів керівником практики;
- експорт звітів у формат CSV;
- логування службових подій, помилок і команд користувача.

## Технології

- **Node.js** — серверна платформа;
- **TypeScript** — мова реалізації з типізацією;
- **Telegraf** — бібліотека для роботи з Telegram Bot API;
- **SQLite** — база даних для локальної розробки та тестування;
- **Docker** — контейнеризація застосунку.

## Команди бота

### Команди користувача

- `/start` — початок роботи з ботом і коротка довідка;
- `/help` — список доступних команд;
- `/register ПІБ | Група` — реєстрація користувача;
- `/tasks` — перегляд актуальних задач;
- `/report текст` — подання щоденного звіту;
- `/taskstatus ID | in_progress` або `/taskstatus ID | done` — зміна статусу задачі;
- `/myid` — показ власного Telegram ID.

### Команди адміністратора

- `/addtask Назва | Опис | YYYY-MM-DD` — створення нової задачі;
- `/reports` — перегляд звітів практикантів;
- `/export` — експорт звітів у CSV.

## Змінні середовища

Перед запуском потрібно створити файл `.env` на основі `.env.example`.

### Приклад `.env.example`

```env
BOT_TOKEN=your_telegram_bot_token
DATABASE_URL=/app/data/practice-bot.db
ADMIN_IDS=123456789
```

### Пояснення

- `BOT_TOKEN` — токен Telegram-бота, отриманий через BotFather;
- `DATABASE_URL` — шлях до SQLite-бази даних;
- `ADMIN_IDS` — Telegram ID керівника практики або список ID через кому.

## Встановлення залежностей

У корені проєкту виконайте:

```bash
npm install
```

## Локальний запуск у режимі розробки

```bash
npm run dev
```

Після запуску бот повинен підключитися до Telegram, ініціалізувати базу даних і почати приймати команди. Для локального запуску у вихідних вимогах також передбачено використання `.env` на основі `.env.example`.

## Збірка і запуск після компіляції

```bash
npm run build
npm start
```

## Запуск через Docker

### Збірка образу

```bash
docker build -t practice-telegram-bot .
```

### Створення папки для даних

```powershell
mkdir data
```

### Запуск контейнера у PowerShell

```powershell
docker run --env-file .env -v "${PWD}\data:/app/data" practice-telegram-bot
```

### Запуск контейнера у Bash/Linux/macOS

```bash
docker run --env-file .env -v "$(pwd)/data:/app/data" practice-telegram-bot
```

Папка `data` монтується в контейнер, щоб SQLite-база не зникала після зупинки або повторного запуску контейнера.

## Структура бази даних

У проєкті використовуються чотири основні таблиці:

### `users`

Зберігає зареєстрованих практикантів і адміністраторів.

Основні поля:

- `id`
- `telegram_id`
- `full_name`
- `group_name`
- `role`
- `created_at`

### `tasks`

Зберігає задачі, дедлайни та статуси.

Основні поля:

- `id`
- `title`
- `description`
- `deadline`
- `status`
- `created_by`

### `reports`

Зберігає щоденні звіти практикантів.

Основні поля:

- `id`
- `user_id`
- `report_date`
- `text`
- `created_at`

### `logs`

Зберігає службові події та помилки.

Основні поля:

- `id`
- `level`
- `message`
- `context`
- `created_at`

## Тестування

Під час перевірки функціональності протестовано такі сценарії:

1. виконання `/start` і отримання вітального повідомлення;
2. реєстрація користувача через `/register`;
3. перегляд актуальних задач через `/tasks`;
4. обробка порожнього `/report`;
5. збереження коректного щоденного звіту;
6. заборона доступу до `/export` для звичайного користувача;
7. формування CSV-файлу через `/export` для адміністратора;
8. зміна статусу задачі;
9. перевірка роботи після перезапуску.

## Безпека

- токен Telegram-бота не зберігається у вихідному коді;
- доступ до адміністративних команд обмежений через `ADMIN_IDS`;
- помилки та службові події логуються;
- передбачено обробку типових помилок введення.
